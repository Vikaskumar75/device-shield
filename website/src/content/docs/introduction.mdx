`device_shield` is a Flutter plugin that tells your app whether it is running
on a device that has been modified or is being inspected. It covers:

- **Root** (Android) and **jailbreak** (iOS)
- **Emulators** and the **iOS Simulator**
- An attached **debugger**
- **Mock (fake) locations**
- **Screenshots** and **screen recording**

It can also **block screenshots** on Android and **blur the app-switcher
snapshot** on both platforms.

## How it works

Each check is a Dart `Detector`. Calling its `check()` method asks the native
side (Kotlin on Android, Swift on iOS) to inspect the device. You get back a
`DetectionResult` that says:

- whether anything was **detected**,
- **which signals** fired, as evidence you can inspect,
- whether the check **applies** on this platform, and
- whether it **completed** or **failed**.

Nothing is sent over the network and nothing is stored. Your app decides what
to do with each result. See [Detection results](../concepts/detection-results/).

## Project status

<Aside type="caution" title="Pre-release">
  `device_shield` isn't on pub.dev yet, and the public API will change before
  0.1.0. Pin to a specific commit if you try it.
</Aside>

What that means in practice:

- **Android has not been run on a physical device or emulator.** The native
  code compiles and its decision logic is unit-tested, but real-device
  behaviour is unverified.
- **iOS has been run on the Simulator only.** Nothing has been tested on a
  physical iPhone.
- **iOS screenshot protection does not work** and shouldn't be used.
- **Each check reports `detected: true` as soon as a single signal fires**,
  including weak ones. Read the signals, not only the flag. See
  [Detection results](../concepts/detection-results/#detected-and-confidence).

[Platform support](../reference/platform-support/) lists exactly what has
been verified where.
